# ToB 产品通用模式库

> 中国 ToB 软件产品的共性分析框架和模式参考。生成 discovery 和 PRD 时参考此文档。
> 关联文档：[[permission-patterns]]（权限体系设计）、[[industry-templates]]（行业功能模板）

## 1. ToB 产品分析维度

分析任何 ToB 产品需求时，必须覆盖以下 6 个维度：

### 1.1 客户背景

| 分析项 | 必须回答的问题 |
|--------|----------------|
| 行业类型 | 客户属于什么行业？行业有什么监管/合规要求？ |
| 组织规模 | 集团？单体公司？有多少分公司/部门/员工？ |
| 现有系统 | 当前用什么系统？痛点在哪里？ |
| 数字化程度 | 业务流程有多少已经线上化？有多少还在手工/纸质？ |

### 1.2 组织架构

ToB 系统的组织模型通常是以下层级之一：

- **集团型**：集团 → 分公司 → 部门 → 岗位 → 员工（5层）
- **多公司型**：公司 → 部门 → 岗位 → 员工（4层）
- **单体型**：部门 → 岗位 → 员工（3层）

**组织架构影响权限设计**：层级越深，数据隔离和跨组织查看越复杂。

### 1.3 业务流程

ToB 业务流程的典型模式：

| 流程类型 | 特征 | 举例 |
|----------|------|------|
| 简单CRUD | 创建 → 编辑 → 查看 → 删除 | 基础数据管理 |
| 状态流转 | 创建 → 提交 → 状态变更 → 结束 | 订单、工单 |
| 审批流转 | 创建 → 多级审批 → 归档 | 合同、报销、采购 |
| 协作流转 | 多人参与 → 分工执行 → 汇总 | 项目管理、任务分配 |

### 1.4 数据口径

ToB 系统中常见的争议焦点，必须在 PRD 中明确定义：

| 口径类型 | 争议点 | 定义方式 |
|----------|--------|----------|
| 金额口径 | 含税/不含税 | 明确字段命名：合同金额(含税) vs 合同金额(不含税) |
| 归属口径 | 按人/按部门/按客户 | 明确归属规则和变更后处理 |
| 统计口径 | 按创建时间/按完成时间 | 明确统计维度 |
| 计算口径 | 利润率计算公式 | 明确计算公式 |
| 有效性口径 | 已作废是否计入统计 | 明确统计是否排除已作废数据 |

### 1.5 集成与对接

中国 ToB 常见集成系统分类：

| 类别 | 常见系统 | 集成方式 |
|------|----------|----------|
| 协作平台 | 钉钉、企业微信、飞书 | API推送消息/审批 |
| OA系统 | 泛微、蓝凌、致远 | API/中间件 |
| 财务系统 | 用友、金蝶 | 数据同步 |
| ERP | SAP、Oracle | 数据同步/中间件 |
| MES | 各行业定制 | 数据采集 |
| 身份认证 | LDAP/AD、统一认证 | SSO集成 |

### 1.6 部署约束

| 部署类型 | 特点 | 需要考虑的 |
|----------|------|------------|
| 公有云SaaS | 多租户 | 数据隔离、租户配置 |
| 私有化部署 | 单租户 | 客户服务器环境、运维责任 |
| 内网部署 | 无外网 | 无法用CDN、无法实时推送外部消息 |
| 国产化 | 信创要求 | 国产OS、国产DB、国产中间件 |

## 2. 角色 Archetype

ToB 系统中的角色几乎都可以归为以下 archetype：

| Archetype | 职责 | 数据范围 | 典型操作 |
|-----------|------|----------|----------|
| 超级管理员 | 系统配置、全局管理 | 全系统 | 配置流程、分配权限、系统参数 |
| 组织管理员 | 本组织管理 | 本组织及下属 | 管理本组织用户、查看本组织数据 |
| 业务操作人 | 日常业务操作 | 本人创建 | 创建、编辑、提交、查看个人数据 |
| 审批人 | 审批决策 | 待审批数据 | 审批通过、退回 |
| 数据管理员 | 数据维护 | 全系统或本组织 | 导入导出、数据清理、数据校验 |
| 外部用户 | 有限访问 | 授权范围内的数据 | 查看、有限提交（如供应商报价） |
| 报表查看者 | 只读查看 | 授权范围 | 查看报表、导出 |

### Archetype → 行业角色映射

各行业预设中的具体角色与 archetype 的对应关系（详细行业模板见 [[industry-templates]]）：

| Archetype | 金融业 | 教育业 | 制造业 |
|-----------|--------|--------|--------|
| 超级管理员 | IT运维 | 系统管理员 | 系统管理员 |
| 组织管理员 | 合规总监、业务主管 | 校长/教务主任 | 集团生产总监、工厂厂长 |
| 业务操作人 | 柜员/运营 | 教师 | 班组长、仓管员 |
| 审批人 | 风控经理 | 年级组长 | 车间主任 |
| 数据管理员 | 审计 | 行政人员 | 质检员 |
| 外部用户 | 客户(外部) | 学生、家长 | 外部供应商(可选) |
| 报表查看者 | 财务 | 家长(报表受限) | 设备工程师(设备报表) |

## 3. 场景分类模板

ToB 系统的核心场景几乎都可以归为以下类别：

### 3.1 列表浏览场景

**触发**：用户进入功能模块，浏览数据列表
**核心需求**：
- 筛选条件（组合筛选、快捷筛选）
- 表格展示（列选择、排序、固定列）
- 分页（常规分页、虚拟滚动）
- 批量操作（批量删除、批量导出）
- 数据范围（按权限过滤）

### 3.2 创建提交场景

**触发**：用户需要新增一条业务数据
**核心需求**：
- 表单设计（分步表单 vs 单页表单）
- 字段校验（必填、格式、关联校验）
- 联动逻辑（选择客户后自动填充联系方式）
- 保存策略（草稿保存、自动保存）
- 关联数据（选择下拉选项来自其他模块数据）

### 3.3 审批流转场景

**触发**：业务数据需要经过审批确认
**核心需求**：
- 审批人确定规则（直属上级、角色指定、金额条件）
- 审批操作（通过、退回、转审）
- 退回规则（退回到哪一步）
- 撤回规则（提交后能否撤回）
- 超时处理（审批超时提醒、自动通过/升级）
- 通知机制（审批通知、结果通知）

### 3.4 报表查看场景

**触发**：管理层需要查看业务数据分析
**核心需求**：
- 报表类型（汇总报表、明细报表、趋势报表）
- 数据维度（按时间、按组织、按类型）
- 图表展示（表格、柱状图、折线图、饼图）
- 导出格式（Excel、PDF）
- 数据权限（不同角色看不同范围的数据）

### 3.5 数据导入导出场景

**触发**：批量数据录入或数据分享
**核心需求**：
- 导入模板（Excel模板下载、字段说明）
- 导入校验（数据格式校验、重复检测、必填检测）
- 导入结果反馈（成功数量、失败数量、失败原因）
- 导出范围（按筛选条件导出、按权限范围导出）
- 导出格式（Excel、CSV）

### 3.6 系统配置场景

**触发**：管理员配置系统参数
**核心需求**：
- 流程配置（审批层级、审批人规则）
- 数据字典（枚举值管理、分类管理）
- 角色权限配置（菜单权限、操作权限、数据权限）
- 系统参数（全局参数、业务参数）
- 组织管理（组织架构维护、岗位维护）

## 4. 中国 ToB 产品常见业务规则模式

| 规则模式 | 描述 | 举例 |
|----------|------|------|
| 金额条件分支 | 根据金额大小触发不同审批层级 | 金额<5万一级审批，>5万二级审批 |
| 时间条件 | 根据时间触发不同行为 | 合同到期前7天提醒续签 |
| 状态互斥 | 同一数据不能同时处于两个状态 | 草稿不能同时审批 |
| 数据锁定 | 审批中数据不可编辑 | 审批通过前不可修改金额 |
| 操作权限条件 | 不同状态可执行不同操作 | 草稿可编辑删除，审批中不可 |
| 归属继承 | 子数据继承父数据归属 | 合同条款继承合同归属 |
| 级联删除 | 删除父数据时处理子数据 | 删除合同提示"有付款记录不可删除" |
| 唯一性约束 | 数据不能重复 | 同一客户同一年度不能有两份同类型合同 |
| 编号规则 | 自动编号格式 | CONTRACT-YYYYMMDD-NNN |
