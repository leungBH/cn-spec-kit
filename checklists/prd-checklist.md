# PRD 完整性检查清单

> 生成 PRD 后对照此清单自检，缺什么补什么。

---

## 1. 项目背景完整性

- [ ] 客户行业是否明确？（不仅是行业名称，还要有行业特征）
- [ ] 客户规模是否明确？（组织层级、用户数量）
- [ ] 现有系统痛点是否描述？（至少3个痛点）
- [ ] 业务目标是否量化？（有可衡量的成功指标）
- [ ] 项目范围是否分一期/二期？（不做哪些也写清楚）

## 2. 角色定义完整性

- [ ] 组织层级是否画出？（集团/分公司/部门/岗位/员工）
- [ ] 操作角色是否列出？（每个角色的职责概述和使用频率）
- [ ] 是否覆盖外部用户？（供应商、客户账号等）
- [ ] 是否覆盖审批人角色？（谁审批什么）
- [ ] 是否覆盖数据管理员角色？（谁管理数据字典、系统配置）

## 3. 功能清单完整性

- [ ] 是否到三级操作层级？（一级模块 → 二级功能 → 三级操作）
- [ ] 每个三级操作是否标注优先级？（P0/P1/P2）
- [ ] 每个功能是否标注一期/二期归属？
- [ ] 是否覆盖列表浏览、创建提交、审批流转三类核心场景？
- [ ] 是否覆盖导入导出、报表查看、系统配置场景？
- [ ] 是否覆盖非功能需求对应的功能？（如登录认证、数据备份）

## 4. 业务场景完整性

- [ ] 每个核心场景是否写了触发条件？
- [ ] 每个核心场景是否写了操作角色？
- [ ] 每个核心场景是否写了操作流程步骤？
- [ ] 每个核心场景是否写了输出结果？
- [ ] 每个核心场景是否写了异常情况？
- [ ] 是否覆盖正常流程和异常流程？

## 5. 非功能需求完整性

- [ ] 性能需求是否有量化指标？（加载时间、并发数、查询速度）
- [ ] 安全需求是否覆盖？（认证、数据隔离、审计、备份）
- [ ] 部署需求是否明确？（公有云/私有化、数据库、等保）
- [ ] 集成需求是否列出？（对接哪些系统、方式、数据流向）
- [ ] 是否考虑国产化要求？（国产数据库、国产OS）

## 6. 数据口径完整性

- [ ] 金额口径是否定义？（含税/不含税）
- [ ] 归属口径是否定义？（按人/按部门/按客户）
- [ ] 统计口径是否定义？（按创建时间/完成时间）
- [ ] 是否定义了数据排除规则？（已作废不计入统计等）

## 7. 交付计划完整性

- [ ] 里程碑是否分阶段？（核心功能 → 完整功能 → 集成上线）
- [ ] 每个里程碑是否有验收方式？
- [ ] 范围边界是否明确？（一期做什么/不做什么/二期规划什么）
