# 跨步骤一致性检查定义

在关键步骤完成后，自动执行跨产物一致性校验。分为阻塞级和警告级。

---

## 🔴 阻塞级检查（必须修复才能继续）

### CC-01: 页面状态 ↔ 业务流程状态一致性

**检查时机**：Step 8（页面原型）完成后

**检查内容**：
1. 读取 `08-page-spec.md` 中每个页面的状态显示定义（如"待审批""已通过""已拒绝"等状态标签）
2. 读取 `07-business-flow.md` 中每个模块的状态定义表
3. 比对：页面规格中的每个状态名称是否在业务流程中有定义
4. 比对：业务流程中的每个状态是否在至少一个页面中可见/可操作

**不一致处理**：
- 页面出现业务流程中没有的状态 → 删除该状态或补充流程定义
- 业务流程有状态但页面未体现 → 补充页面状态显示
- 必须修复后才能进入 Step 9

### CC-02: 权限操作 ↔ 页面按钮一致性

**检查时机**：Step 9（权限矩阵）完成后

**检查内容**：
1. 读取 `10-permission-matrix.md` 中角色×操作权限矩阵的所有操作项
2. 读取 `08-page-spec.md` 中每个页面的按钮操作列表
3. 比对：权限矩阵中的每个操作是否对应一个页面按钮
4. 比对：页面规格中的每个按钮是否在权限矩阵中有权限定义

**不一致处理**：
- 权限矩阵有操作但页面无按钮 → 补充按钮或删除操作
- 页面有按钮但权限矩阵无定义 → 补充权限定义
- 必须修复后才能进入 Step 10

### CC-03: 验收场景 ↔ PRD场景一致性

**检查时机**：Step 10（验收标准）完成后

**检查内容**：
1. 读取 `11-acceptance.md` 中每个功能的验收场景列表
2. 读取 `04-prd.md` 中业务场景描述列表
3. 比对：PRD 中的每个核心场景是否在验收标准中有对应的验收项
4. 比对：验收标准中是否覆盖了 PRD 中所有选定优先级的功能

**不一致处理**：
- PRD 有场景但验收标准未覆盖 → 补充验收项
- 必须修复后才能进入 Step 11

### CC-08: 需求文档角色 ↔ Discovery干系人一致性

**检查时机**：Step 4.5（需求文档）完成后

**检查内容**：
1. 读取 `03-requirement.md` 中的角色列表（来自"角色定义"或"操作角色"章节）
2. 读取 `01-discovery.md` 中的干系人列表
3. 比对：需求文档中的角色与 discovery 干系人是否对齐

**不一致处理**：
- 需求文档遗漏关键干系人 → 补充
- 必须修复后才能进入 Step 5

### CC-09: 需求文档验收指标 ↔ Discovery成功指标一致性

**检查时机**：Step 4.5（需求文档）完成后

**检查内容**：
1. 读取 `03-requirement.md` 中的验收标准章节
2. 读取 `01-discovery.md` 中的"成功指标"或"需求目标"章节
3. 比对：需求文档中的每项量化指标在 discovery 中是否有对应
4. 比对：discovery 中提到的成功指标在需求文档中是否有对应验收项

**不一致处理**：
- 需求文档有验收指标但 discovery 未提到 → 提示用户补充业务目标
- discovery 有成功指标但需求文档无对应 → 补充验收项
- 必须修复后才能进入 Step 5

## 🟡 警告级检查（列出差异，供用户确认）

### CC-04: 权限角色 ↔ PRD角色一致性

**检查时机**：Step 9（权限矩阵）完成后

**检查内容**：
1. 读取 `10-permission-matrix.md` 中的角色列表
2. 读取 `04-prd.md` 中的角色定义表
3. 比对：两个文档中的角色列表是否完全一致

**不一致处理**：
- 列出差异角色，供用户确认是否需要补充或删除
- 不阻塞后续步骤

### CC-05: 研发任务API ↔ 页面操作一致性

**检查时机**：Step 11（研发任务）完成后

**检查内容**：
1. 读取 `12-dev-tasks.md` 中后端任务的 API 接口列表
2. 读取 `08-page-spec.md` 中每个页面的按钮操作和字段列表
3. 比对：页面规格中的每个 CRUD 操作是否在后端 API 中有对应接口
4. 比对：后端 API 的入参/出参是否覆盖页面规格中的字段

**不一致处理**：
- 列出差异（缺接口的字段、缺字段对应的API参数），供用户确认
- 不阻塞后续步骤

### CC-06: DAG依赖 ↔ 页面跳转一致性

**检查时机**：Step 8（页面原型）完成后

**检查内容**：
1. 读取 `06-dependency-dag.md` 中的模块依赖关系
2. 读取 `08-page-spec.md` 中的页面跳转关系
3. 比对：DAG 中有依赖关系的模块，其对应页面之间是否有跳转链接
4. 比对：页面跳转关系是否超出 DAG 定义的范围

**不一致处理**：
- 列出差异，供用户确认
- 不阻塞后续步骤

### CC-07: 研发任务构建顺序 ↔ DAG构建顺序一致性

**检查时机**：Step 11（研发任务）完成后

**检查内容**：
1. 读取 `06-dependency-dag.md` 中的"构建顺序建议"（基于拓扑排序的开发顺序）
2. 读取 `12-dev-tasks.md` 中的任务执行顺序和依赖关系
3. 比对：研发任务的模块开发顺序是否与 DAG 的构建顺序建议一致
4. 比对：研发任务之间的依赖关系是否与 DAG 模块依赖关系一致

**不一致处理**：

- 列出顺序差异，供用户确认是否需要调整研发任务排序
- 不阻塞后续步骤

---

## 检查执行方式

在每个阻塞级检查时机，agent 自动执行：
1. 读取两个产物文件
2. 提取比对维度（状态名、操作名、角色名、场景名等）
3. 逐一比对，记录不一致项
4. 输出检查结果（✅一致 / ❌不一致 + 差异列表）
5. 阻塞级不一致 → 修复产物后重新检查
6. 警告级不一致 → 列出差异，继续下一步
