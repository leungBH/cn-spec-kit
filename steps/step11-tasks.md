# Step 11: 研发任务 (tasks)

读取研发任务模板（按覆盖优先级查找）：
- 先查 `overrides/dev-tasks.md`
- 再查 `presets/<industry>/dev-tasks.md`
- 最后 `templates/dev-tasks.md`

读取 `04-prd.md`、`06-dependency-dag.md`、`07-business-flow.md`、`08-page-spec.md`、`10-permission-matrix.md`、`11-acceptance.md` 和 `05-scope-selection.md` 作为输入。

只对选定优先级的功能拆解详细研发任务。

生成 `12-dev-tasks.md` 和 `13-traceability-matrix.md`。

---

## 研发任务必须包含

### 1. 前端任务（每个选定页面一个任务组）

- 页面开发（含布局、字段、按钮、表格、弹窗）
- 表单校验实现
- 权限控制实现
- 状态流转交互

### 2. 后端任务（每个选定功能模块一个任务组）

- 数据模型设计
- API 接口开发（含入参出参定义）
- 业务逻辑实现（含审批流、状态变更）
- 权限中间件
- 数据口径计算

### 3. 测试任务（按验收标准对应）

- 功能测试（对应验收标准每条）
- 权限测试
- 异常场景测试
- 性能测试

### 4. 任务详情格式

```markdown
### FE-001: 合同列表页面开发
**依赖**: BE-001（合同数据模型）
**预估**: 2天
**验收关联**: AC-001, AC-002
**描述**: 开发合同列表页面，包含筛选、表格、分页、批量操作
```

---

## 并行拆解 FE/BE/TEST 任务

使用 **parallel Agent** 同时拆解三类任务：
- Agent 1：拆解前端任务（基于页面规格）
- Agent 2：拆解后端任务（基于PRD + 流程 + DAG）
- Agent 3：拆解测试任务（基于验收标准）

三类任务拆解完成后，合并写入 `12-dev-tasks.md`。

---

## 13-traceability-matrix.md 必须包含

需求追踪矩阵（表格：需求ID | 业务场景 | 页面 | 字段 | 接口 | 权限 | 验收标准 | 测试用例 | 研发任务）

每行对应一个需求点，所有产物通过需求ID串起来。**只追踪选定优先级的需求**。

---

## 贪量门禁

### 第一层：步骤完整性门禁

- 检查前端任务数 = 选定页面数
- 检查后端任务数 = 选定模块数
- 检查测试任务覆盖所有验收标准
- 检查追踪矩阵行数 = 选定需求总数
- 缺失 ≥ 3 个回到本步补充

### 第二层：外部大模型评审

内部门禁通过后，触发外部大模型评审（详见 `steps/external-review.md`）：

- 评审维度：任务拆解粒度合理性、追踪矩阵完整性、任务依赖关系准确性、构建顺序一致性
- 通过标准：总分 ≥ 75 且无严重问题
- 不通过：根据评审意见调整研发任务，最多重试 3 轮
- 评审结果记录到 `14-review-log.md`

外部评审通过后，全部步骤完成。
