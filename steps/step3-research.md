# Step 3: 竞品调研 (research)

读取刚生成的 `01-discovery.md`，提取业务领域关键词。

## 调研目标

在互联网上大规模检索同类竞品，学习优秀设计（主要是**功能层面**），补充到本产品的功能设计中。

## 调研流程

### 1. 确定搜索关键词

从 discovery 中提取行业 + 业务对象组合。例：
- discovery 识别出"AI/大模型服务"+"Token计费" → 搜索关键词：`Token计费平台`、`Token管理系统`、`AI Token运营`、`大模型API计费`
- discovery 识别出"合同管理" → 搜索关键词：`合同管理系统`、`合同审批平台`、`ToB合同SaaS`

### 2. 大规模搜索（并行 Agent）

使用 **并行 Agent** 同时发起多轮搜索（至少 5 个不同角度的搜索词），每个 Agent 独立执行搜索任务。
- 国内竞品（中文搜索）
- 国际对标产品（英文搜索）
- 行业解决方案（行业+业务组合搜索）
- 开源/社区方案（GitHub 等）
- 产品评测/对比文章

每个搜索词使用一个独立 Agent，并行执行 WebSearch。

### 3. 深度分析（并行 Agent）

对搜索结果中值得深入的产品/方案，使用 **并行 Agent** 同时抓取多个竞品页面，提取：
- **功能清单**：竞品有哪些功能模块？哪些是我们没想到的？
- **功能亮点**：竞品的差异化功能或创新设计
- **交互模式**：竞品的典型操作流程和用户体验模式
- **商业模式**：竞品的定价、分销、充值模式
- **技术架构**：竞品的技术实现方式（API设计、计量方式等）

### 4. 生成调研报告

将调研结果写入 `specs/<序号-功能名>/02-competitive-research.md`

**调研报告必须包含的 5 个章节**：

| 章节 | 内容 |
|------|------|
| 搜索概览 | 使用的搜索词、搜索结果数量、覆盖的竞品数量 |
| 竞品清单 | 竞品名称、定位、目标客户、核心功能、亮点功能 |
| 功能借鉴 | 从竞品中识别的值得借鉴的功能点（按优先级排列） |
| 差距分析 | 我们当前 discovery 中的功能 vs 竞品功能，缺失哪些 |
| 建议补充 | 哪些竞品功能应该补充到我们的 PRD 中（附理由） |

## 竞品驱动追问

调研完成后，如果发现我们缺失的功能，回到 `01-discovery.md` 的"需求追问补充"章节追加竞品驱动的追问结果：

> "竞品调研发现 XX 产品具备 [功能A]，您是否也需要此功能？"

以结构化提问方式逐个追问，每次最多问 2 个问题。追问结果追加到 `01-discovery.md`。

## 🚪 质量门禁

### 第一层：步骤完整性门禁

检查调研报告是否：
- 覆盖至少 3 个竞品
- 识别至少 5 个可借鉴功能点
- 每个功能点有优先级和理由

不足则回到本步扩大搜索范围。

### 第二层：外部大模型评审

内部门禁通过后，触发外部大模型评审（详见 `steps/external-review.md`）：

- 评审维度：竞品覆盖广度、功能借鉴合理性、差距分析深度、建议补充可操作性
- 通过标准：总分 ≥ 75 且无严重问题
- 不通过：根据评审意见补充调研（扩大搜索范围、增加深度分析），最多重试 3 轮
- 评审结果记录到 `10-review-log.md`

外部评审通过后，才能进入 Step 4。
