# Step 5: PRD 生成 (prd)

## 执行步骤

1. 读取 PRD 模板（按覆盖优先级查找）：
   - 先查 `presets/<industry>/prd.md`（行业预设，行业名从 discovery 中获取）
   - 最后 `templates/prd.md`（全局默认）
2. 读取 `01-discovery.md`（含追问补充）、`02-competitive-research.md` 和 `03-requirement.md`（Step 4 生成的需求文档）作为输入
3. 读取 `checklists/prd-checklist.md` 了解质量标准
4. 生成 `04-prd.md`，写入 `specs/<序号-功能名>/`

## PRD 必须包含的章节（严格按模板）

1. 项目概述（背景、目标、范围）
2. 角色定义（组织层级图 + 操作角色表）
3. 功能清单（一级模块 → 二级功能 → 三级操作，表格形式，**每个功能标注 P0/P1/P2 优先级**）
4. 业务场景描述（每个核心场景：触发条件 → 操作流程 → 输出结果）
5. 非功能需求（性能、安全、部署、集成）
6. 数据口径约定
7. 里程碑与交付计划
8. 范围边界（一期范围 vs 二期范围）

## 竞品功能融入

将 Step 3 竞品调研中"建议补充"的功能点，纳入 PRD 功能清单，标注优先级和来源（如"借鉴自XX竞品"）。

## 开发范围选择（原 Step 7 合并至此）

PRD 生成后，**在 04-prd.md 末尾追加"## 开发范围决策"章节**，让用户选择本次开发的范围：

> **请选择本次开发的范围**（影响后续所有产物的详细程度）：

| 选项 | 说明 | 适合场景 |
|------|------|----------|
| P0 核心功能 | 只做最高优先级功能，最小可用版本 | 时间紧张、MVP验证 |
| P0 + P1 标准功能 | 覆盖核心+重要功能，完整业务闭环 | 正常一期交付 |
| P0 + P1 + P2 全量功能 | 包含所有规划功能，最完整版本 | 时间充裕、全面交付 |

用户选择后，在 04-prd.md 末尾记录：

```markdown
## 开发范围决策

**选择**: P0 + P1 标准功能
**包含功能**: （列出选定的功能清单）
**不含功能**: （列出跳过的 P2 功能，简要说明二期规划）
```

### 用户选择后的效果

- 后续所有步骤（业务流程、页面原型、权限矩阵、验收标准、研发任务）**只覆盖选定优先级的功能**
- 未选定的功能在产物中简要提及但不展开详细规格
- 页面原型只生成选定优先级对应的页面 HTML
- 研发任务只拆解选定优先级的功能

后续步骤读取 `04-prd.md` 的"开发范围决策"章节获取范围信息。

## 🚪 质量门禁

### 第一层：步骤完整性门禁

读取 `checklists/prd-checklist.md`，逐条对照 04-prd.md：
- 覆盖率 ≥ 90%：✅ 通过
- 覆盖率 < 70%：❌ 回到本步修补
- "开发范围决策"章节必须存在且包含用户选择 → 缺失则 ❌ 阻塞

### 第二层：外部大模型评审

内部门禁通过后，触发外部大模型评审（详见 `steps/external-review.md`）：

- 评审维度：PRD结构完整性、功能优先级合理性、竞品功能融入充分度、业务场景描述可执行性、非功能需求覆盖度
- 通过标准：总分 ≥ 75 且无严重问题
- 不通过：根据评审意见修补 PRD，最多重试 3 轮
- 评审结果记录到 `10-review-log.md`

外部评审通过后，才能进入 Step 6。
