# Step 4: 需求文档生成 (requirement)

> **位置**：在 Step 3 竞品调研 之后、Step 5 PRD 之前。
> **目的**：在产出正式 PRD 之前，先按用户选择的"需求文档模板"生成一份正式的需求文档（售前/SDD 等格式），用于客户/业务方评审、签字归档或与 AI SDD 环境对接。

---

## 执行步骤

### 4.1 加载可用模板清单

1. 读取 `templates/index.md`，获取所有可用模板的元数据（id / name / description / 章节预览）
2. 如果在 `presets/<industry>/` 中存在 `<id>.md` 覆盖文件，标注为"已定制"
3. 以结构化提问方式向用户展示模板列表，每个选项包含模板名 + 适用场景 + 章节预览

**提问模板**：

```json
{
  "questions": [
    {
      "header": "需求模板",
      "question": "请选择本次需求使用的需求文档模板",
      "multiSelect": false,
      "options": [
        {
          "label": "AI SDD 标准化需求文档",
          "description": "面向 AI 辅助开发环境，按数据/流程/功能开发分类，字段级可追溯、可自动生成代码"
        }
      ]
    }
  ]
}
```

> **如果模板数量 ≥ 3 个**，按 index.md 的顺序展示前 3 个 + "查看更多"。
> **如果用户选择了"暂不选择"**，使用 `index.md` 中的"默认模板选择规则"自动推荐。

### 4.2 加载模板源文件

按覆盖优先级查找模板源文件：
1. 先查 `presets/<industry>/<id>.md`（行业预设，行业名从 discovery 中获取）
2. 再查 `templates/<id>.md`（全局默认）

### 4.3 生成需求文档

读取 `01-discovery.md`（含追问补充）和 `02-competitive-research.md` 作为输入。

按模板结构填充内容，生成 `03-requirement.md`，写入 `specs/<序号-功能名>/`。

**必须遵守**：
- 严格按模板章节结构填充，不遗漏任何章节
- 竞品调研中"建议补充"的功能点纳入需求文档
- 数据口径、审批流程等阻塞维度的结论必须体现在需求文档中

### 4.4 模板覆盖规则

如果 `presets/<industry>/` 下存在对应模板文件，**行业预设优先于全局默认**。预设文件可以：
- 完全覆盖全局模板（替换整个文件）
- 部分覆盖（只覆盖特定章节，其余继承全局模板）

---

## 🚪 质量门禁

### 第一层：步骤完整性门禁

读取 `checklists/requirement-checklist.md`，逐条对照 03-requirement.md：
- 覆盖率 ≥ 90%：✅ 通过
- 覆盖率 < 70%：❌ 回到本步修补

### 第二层：外部大模型评审

内部门禁通过后，触发外部大模型评审（详见 `steps/external-review.md`）：

- 评审维度：模板覆盖完整性、业务逻辑准确性、功能描述可执行性、数据口径一致性、竞品功能融入充分度
- 通过标准：总分 ≥ 75 且无严重问题
- 不通过：根据评审意见优化需求文档，最多重试 3 轮
- 评审结果记录到 `10-review-log.md`

外部评审通过后，才能进入 Step 5。
