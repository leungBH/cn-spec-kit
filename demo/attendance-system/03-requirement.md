## 2. 背景价值

### 2.1 业务背景
公司规模 800 人，3 个厂区，目前使用纸质签到 + 钉钉群接龙 + Excel 统计的方式管理考勤。HR 每月需投入 3 人天做考勤报表，且与工资核算脱节，经常出错。

### 2.2 核心价值
- **HR 效率提升**: 月度考勤处理从 3 人天降至 0.5 人天
- **数据准确性**: 工资核算错误率从 5% 降至 0.5% 以下
- **流程规范化**: 补卡/请假/加班流程线上化、可追溯
- **管理可视化**: 部门负责人实时掌握团队出勤状况
- **多厂区统一**: 集团账号下统一管理多厂区考勤

### 2.3 验收标准（业务级）

| 编号 | 指标 | 目标 |
|------|------|------|
| AC-BIZ-001 | HR 月度考勤处理耗时 | ≤ 0.5 人天 |
| AC-BIZ-002 | 月度考勤报表生成时间 | 月初 1 个工作日内 |
| AC-BIZ-003 | 工资核算错误率 | ≤ 0.5% |
| AC-BIZ-004 | 异常考勤处理时长 | 平均 ≤ 0.5 天 |
| AC-BIZ-005 | 员工打卡合规率 | ≥ 95% |

## 3. 约束边界

### 3.1 业务约束
- 3 个厂区，需 GPS 围栏打卡（每个厂区独立围栏）
- 部分员工倒班制（白班/夜班/中班）
- 需支持历史数据导入（过去 1 年纸质记录）
- 数据隔离口径：按"员工所属部门"判断

### 3.2 技术约束
- 移动端仅支持 H5（钉钉/企业微信内嵌），不开发原生 App
- 数据库：MySQL 8.0
- 后端：Java + Spring Boot
- 前端：Vue 3 + Vant
- 部署：阿里云（客户已有云账号）

### 3.3 时间约束
- 交付时间：2026-09-30（3 个月）
- 一期范围：P0 + P1 功能
- 二期规划：P2 功能（弹性排班、年假累计等）

### 3.4 范围之外（一期明确不做）
- 门禁硬件对接
- 工资核算完整模块（仅提供数据接口）
- 灵活排班系统
- 员工自助年假额度管理

## 4. 功能开发需求

> 本节按功能模块组织，每个模块包含功能描述、字段定义、交互规则、验收标准。

### 4.1 员工打卡模块

#### 功能描述
员工通过手机进行上下班打卡，支持 GPS 定位 + 拍照反代打卡 + 蓝牙辅助定位。

#### 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 打卡ID | string | 是 | 系统生成 UUID |
| 员工ID | string | 是 | 关联员工表 |
| 打卡时间 | datetime | 是 | yyyy-MM-dd HH:mm:ss |
| 打卡类型 | enum | 是 | 上班卡/下班卡/午休出/午休入 |
| 打卡地点 | object | 是 | {厂区ID, 围栏ID, 纬度, 经度, 距离} |
| 打卡方式 | enum | 是 | GPS/蓝牙/人脸 |
| 打卡照片 | string | 否 | 拍照反代打卡时上传 |
| 设备信息 | object | 否 | {设备型号, 系统版本, App版本} |
| 是否异常 | bool | 是 | 缺卡/迟到/早退/正常 |
| 异常原因 | string | 否 | 异常时填写 |

#### 交互规则
1. 早班（08:00-08:30）/ 晚班（17:00-17:30）：30 分钟内打卡为正常
2. 超时 30 分钟打卡：标记为迟到/早退
3. 未打卡：标记为缺卡
4. 缺卡/迟到可申请补卡，3 天内可补

#### 验收标准
- **AC-FN-001**: 员工在厂区 200 米范围内可成功打卡
- **AC-FN-002**: 离开厂区范围打卡时系统提示"不在打卡范围"
- **AC-FN-003**: 迟到 1 分钟内打卡成功，超过 1 分钟标记异常
- **AC-FN-004**: 拍照打卡时照片必须包含人脸，否则拒绝

### 4.2 请假管理模块

#### 功能描述
员工提交请假申请（事假/病假/年假/调休），按层级审批。

#### 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 请假ID | string | 是 | 系统生成 |
| 员工ID | string | 是 | - |
| 请假类型 | enum | 是 | 事假/病假/年假/调休/婚假/产假/陪产假/丧假 |
| 开始时间 | datetime | 是 | - |
| 结束时间 | datetime | 是 | - |
| 请假天数 | decimal | 是 | 自动计算 |
| 请假原因 | string | 是 | 至少 10 字 |
| 证明材料 | array | 否 | 病假/婚假等需要上传 |
| 审批流 | array | 是 | 一级/二级/三级审批人 |
| 审批状态 | enum | 是 | 待审批/已通过/已拒绝/已撤销 |
| 审批意见 | object | 否 | {审批人, 意见, 时间} |

#### 交互规则
1. **请假天数 ≤ 2**: 直属上级审批
2. **请假天数 3-5**: 直属上级 → 部门负责人
3. **请假天数 ≥ 6 或跨厂区**: 一级 → 二级 → HR 经理
4. HR 经理可越级审批紧急请假

#### 验收标准
- **AC-FN-101**: 提交请假后自动通知审批人（钉钉/企业微信）
- **AC-FN-102**: 审批人 24 小时内未处理则自动升级到上一级
- **AC-FN-103**: 请假通过后自动从年假/调休余额扣减
- **AC-FN-104**: 请假与已有打卡冲突时自动标记为异常

### 4.3 补卡管理模块

#### 功能描述
员工因忘打卡或系统故障申请补卡。

#### 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 补卡ID | string | 是 | - |
| 员工ID | string | 是 | - |
| 补卡日期 | date | 是 | - |
| 补卡时段 | enum | 是 | 上班/下班/午休出/午休入 |
| 补卡时间 | time | 是 | 申请补的具体时间 |
| 补卡原因 | string | 是 | 至少 10 字 |
| 审批人 | string | 是 | 直属上级 |
| 审批状态 | enum | 是 | 待审批/已通过/已拒绝 |
| 审批意见 | string | 否 | - |

#### 交互规则
1. 仅支持补 3 天内的卡
2. 每月最多补卡 3 次
3. 直属上级审批

#### 验收标准
- **AC-FN-201**: 补卡通过后自动更新该日打卡记录
- **AC-FN-202**: 补卡次数超过月限时系统拒绝
- **AC-FN-203**: 补卡时间超过 3 天系统提示"已超出补卡期限"

### 4.4 加班管理模块

#### 功能描述
员工申请加班，自动换算调休或加班费。

#### 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 加班ID | string | 是 | - |
| 员工ID | string | 是 | - |
| 加班日期 | date | 是 | - |
| 加班开始 | time | 是 | - |
| 加班结束 | time | 是 | - |
| 加班时长 | decimal | 是 | 自动计算（小时） |
| 加班类型 | enum | 是 | 工作日/周末/法定节假日 |
| 补偿方式 | enum | 是 | 调休/加班费 |
| 加班原因 | string | 是 | - |
| 审批人 | string | 是 | 直属上级 |
| 审批状态 | enum | 是 | 待审批/已通过/已拒绝 |

#### 交互规则
1. 工作日加班：1 小时 = 1 小时调休 或 1.5 倍工资
2. 周末加班：1 小时 = 1.5 小时调休 或 2 倍工资
3. 法定节假日：1 小时 = 2 小时调休 或 3 倍工资
4. 加班可事前申请或事后 3 天内补申请

#### 验收标准
- **AC-FN-301**: 加班审批通过后自动计入调休余额或生成加班费记录
- **AC-FN-302**: 加班时长 ≤ 0 拒绝提交
- **AC-FN-303**: 法定节假日加班自动按 3 倍计算

### 4.5 月度报表模块

#### 功能描述
HR 经理导出月度考勤报表，自动按部门分组。

#### 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 报表ID | string | 是 | - |
| 月份 | string | 是 | yyyy-MM |
| 生成时间 | datetime | 是 | - |
| 部门列表 | array | 是 | 全公司部门 |
| 员工考勤数据 | array | 是 | {员工ID, 出勤天数, 缺卡次数, 迟到次数, 早退次数, 请假天数, 加班时长, 调休余额} |
| 异常汇总 | object | 是 | 各类异常总数 |
| 导出格式 | enum | 是 | Excel/PDF |

#### 交互规则
1. 月初第 1 个工作日 08:00 自动生成
2. 自动发送给 HR 经理和各部门负责人
3. 部门负责人仅看本部门数据
4. 报表可追溯任意一天的打卡详情

#### 验收标准
- **AC-FN-401**: 报表生成时间 ≤ 10 分钟（800 人数据量）
- **AC-FN-402**: 报表数据与月度工资核算系统对接（提供数据接口）
- **AC-FN-403**: 部门负责人收到的报表仅含本部门员工

### 4.6 基础数据管理模块

#### 功能描述
HR 维护员工、部门、班次、考勤组等基础数据。

#### 字段定义
- **员工**: 员工ID、姓名、工号、所属部门、岗位、工种、入职日期、手机号
- **部门**: 部门ID、部门名称、上级部门、部门负责人
- **班次**: 班次ID、班次名称、班次类型（白/中/夜）、开始时间、结束时间
- **考勤组**: 考勤组ID、组名、关联员工、关联班次、关联厂区

#### 验收标准
- **AC-FN-501**: 员工新增后自动关联默认考勤组
- **AC-FN-502**: 部门调整时自动更新员工所属部门
- **AC-FN-503**: 历史纸质记录可通过 Excel 批量导入
